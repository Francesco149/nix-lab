5## Project
6
7Personal NixOS flake for homelab hosts, built on the local `nut` flake library.
8The repo should stay easy for humans and coding agents to resume without
9re-learning project conventions each session.
10
11## Current Goals
12
13- Keep `flake.nix` as the host/module wiring source of truth.
14- Keep shared constants in `lib/lab.nix`.
15- Provide a system-wide custom Neovim launcher named `e` for interactive hosts
16 without changing the clean `neovim` package used by OpenVSCode.
17- Keep interactive tool colors tied to `lib/lab.nix` without overriding the
18 terminal background.

50## Wslop Cold Backup
51
52`wslop-backup` (hosts/wslop/backup.nix) backs up the WSL guest rootfs and a
53curated list of windows work dirs to cold. Usage and design live in
54docs/OPERATIONS.md.
55
56Decisions:
57
58- 2026-06-14 redesign: the windows side no longer mirrors whole `/mnt` drives
59 (that pulled `Windows/`, `Program Files/`, the 414G WSL `ext4.vhdx` under
60 AppData, and locked system files over slow 9p, and failed instantly on a
61 missing `windows/<drive>` dest dir). It is now an explicit
62 `backup.wslop.windows.{work,optional}` list of actual work dirs; capture/
63 trace dirs drop image/video (`image-junk`), keeping only binary traces.
64 rootfs is unchanged — it reads native ext4 `/` (not 9p) and is a cheap
65 rsync incremental. Fixes shipped: `--mkpath` (the instant-failure bug),
66 dataset `acltype=posixacl` (killed the `set_acl Operation not supported`
67 spam on `/var/log/journal`), and skip wake/unlock when cold is already up.
68- WSL2 NAT drops subnet-directed broadcasts (tested with a sniffer on code:
69 unicast UDP arrives, broadcast never does), so wslop relays wake+unlock
70 through `ssh root@code cold-unlock --host cold` instead of sending WoL.
71- Push runs as root@cold: the interactive ssh keys are authorized everywhere
72 already, cold ships rsync via NixOS defaultPackages, and root can create
73 datasets/snapshots without `zfs allow` — so the manual command works without
74 redeploying cold or code.
75- Skipping the cold wake-up when nothing changed was considered and dropped:
76 `code` is a VM on proxmox and always has new data, so the check would never
77 skip anything.

134## Video Understanding / Local VLM Eval (2026-06-15)
135
136Investigated replacing the broken `llama-video` (Cobdog patch) setup. **Upstream
137llama.cpp has native video since `8f83d6c` (2026-06-08)** — temporal-merge +
138M-RoPE + ffmpeg frame extraction + interleaved timestamps — matching/beating the
139patch, no patch needed. Proven on lame (7800XT/Vulkan) with the existing
140`Qwen3.6-35B-A3B` + mmproj: high-quality, temporally-ordered descriptions
141(user-confirmed ≥ llama-video). Full findings + reusable testbed live in
142`research/video-understanding/` (build/run scripts, perf matrix, model rec).
143
144Key results:
145- Native temporal video is **Qwen-VL-lineage only** (our Qwen3.6 models qualify).
146 nixpkgs `llama-cpp` b9503 predates video by 4 days → build from source for now
147 (`research/.../scripts/build-llama.sh`), or wait for nixpkgs ≥ ~b9510.
148- Perf (7800XT 16 G, fully on GPU): MoE quants that fit VRAM ≈ **120 t/s**;
149 dense-27B ≈ 31 t/s, **+MTP ≈ 54 t/s (1.74×)**; the offloaded `Q4_K_P` (current
150 prod config) only **14–25 t/s**. The 3080 (10 G) is VRAM-bound for 27–35 B →
151 the **7800XT is the better card** here.
152- Two real gotchas (documented): the helper's **ffmpeg-feeder SIGPIPE bug**
153 (needs SIG_IGN; one-line upstream fix worth a PR) and the **video token budget**
154 (~1.3k tok/sec-of-video at full res → cap `--image-max-tokens`/fps for long clips).
155- **MTP + `--mmproj` works for video** (tested); mmproj is shareable across
156 Qwen3.6 finetunes of the same base.
